# 转向决策：废弃自动执行，改为只读分步指导

## 用户决策

2026-10-27，用户在核对现有四阶段脚本后明确："我们需要的脚本更像是 ssh 增强步骤的指导，而不是乱作为、瞎回退"。并给出三阶段划分：stage0 检查当前状态；stage1 负责切端口、切密钥、检查 sudo 组新用户是否可用；stage2 增加 nft 白名单、停止 root 登录与密码登录、最终确认加固效果；每个脚本按内置只读方案输出当前步骤的确认与指导操作及说明；执行可交给操作员或智能体；旧执行体系的处置由实现方决定。

## 审查证据（本次转向的依据）

- stage0 `--guide` 是代执行而非指导：`Workflow.run` 直接调用 stage1/2 的 `--apply`（legacy stage0-audit.sh:1114-1124）。
- 每次 apply 安装 systemd 自动恢复定时器（legacy stage1-newport.sh:887-914），900 秒未确认即无人值守自动回滚。
- 回滚先停 SSH（`stop_ssh_entry`→`systemctl stop ssh.service ssh.socket`，legacy stage1-newport.sh:933/1013），恢复失败再停一次（stage1:1081-1083、stage2:913-915）——"恢复失败即将全部 SSH 接入掐断"，与 [[BUG-015]] 缺陷族和 [[BUG-016]] 真实失联事故直接相关。
- 救援通道 `RESCUE_CONFIRMED=yes` 只是配置声明，未被真实验证；事故时 VNC 实际不可用。

## 交付内容

1. 三个只读指导脚本（仓库根目录）：`stage0-check.sh`、`stage1-port-key.sh`、`stage2-lockdown.sh`。共同契约：命令白名单 + 全部文件系统访问经 `System` 抽象；不写状态文件、不装定时器、不代执行、无自动回滚；文本与 JSON 双输出。
2. 旧体系整体迁入 `legacy/`（四个 stage + 三个兼容入口 + 旧测试 + 旧设计文档），加废弃说明 `legacy/README.md`，保持字节冻结用于取证与远端旧事务对照。
3. 新测试套件：`tests/guide-support.py`（内嵌实现提取 + 内存桩件）、`tests/test-guides.py`、`tests/run-tests.py`、`tests/README.md`。
4. 文档：本检查点；`plans/DESIGN-v2.md` 重写为 v2 只读指导设计（v1 设计原文随 `legacy/plans/DESIGN.md` 冻结）；根目录 `README.md` 双语重写。

## 关键设计点

- **无状态推断**：不写 `/var/lib` 状态，位置由只读证据推断（会话四元组、监听、磁盘配置、`sshd -T -C` 上下文、nft 字面量摘要、账户/公钥、备份目录、重启时间比较）。
- **硬门槛**：救援通道演练（`--rescue-confirmed`）、手工备份、新端口"外部公钥会话重跑"证明（密码会话不算通过）、白名单来源自检（当前来源不在 `--allow` 内即硬阻断）、禁用密码前置、重启持久化证据。
- **智能体执行契约**：只执行 `blocked_by` 为空的步骤；每步执行后重跑核对；失败即停并打印手工恢复命令；云安全组操作只能由人完成。

## 验证

- `python3 tests/run-tests.py`：**37 项全部通过**（脚本 `bash -n`、内嵌边界、只读白名单与实测调用审计、`SSH_CONNECTION`/journal/`ss`/`(Stream)`/nft 单元素折叠解析、白名单五路径判定、stage1 六用例、stage2 五用例、stage0 定位与退出码、参数校验、JSON 结构）。
- 沙箱实际运行：非 root 降级路径、采集缺口与旧版痕迹报警、退出码 2/1 行为符合预期（无 systemd/nft 的容器环境）。
- 未执行任何远端操作：未上传、未连接远端、未修改任何真实服务器。
