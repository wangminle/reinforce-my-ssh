## BUG-053：生产修复有效，回归夹具需修正

生成的加载器已有 DefaultDependencies=no、显式 local-fs/network-pre/SSH/shutdown 顺序，安装到 sysinit.target，消除了原来经 basic.target 与 sockets.target 构成的排序环。

当前 `tests/test-review-fixes.py` 的 `test_loader_early_boot_unit_and_transaction_have_no_ordering_cycle` 把 basic.target 等 target 写成空的 `[Unit]`。缺少 basic.target 的 After=sockets.target 等边，因此旧配置 verify 也返回 0、没有环；测试在第 255 行的旧图断言失败，根本没有执行到新图校验。Windows 跳过这个原生子项后，无法暴露此问题。

本轮独立补充的临时图至少包含：

- basic.target：Requires=sysinit.target，Wants=sockets.target，After=sysinit.target sockets.target。
- sysinit.target：Wants/After=local-fs.target。
- multi-user.target：Requires/After=basic.target。
- local-fs.target 和 shutdown.target：DefaultDependencies=no。
- ssh.socket 挂入 sockets.target.wants；加载器分别按旧/新配置挂入 multi-user.target.wants 或 sysinit.target.wants。

在完全相同的补充图中，旧配置出现 basic.target → sockets.target → ssh.socket → ssh-allowlist.service → basic.target 的环，新配置 verify 返回 0。只在临时目录运行 [systemd-analyze verify](https://www.freedesktop.org/software/systemd/man/latest/systemd-analyze.html)，没有加载或启动实际 SSH 单元。建议将完整依赖边及安装链接纳入正式回归，不能仅删去旧图失败断言。

## BUG-054：接口限定不再被抹去

stage0/stage2 的 nft 路径要求没有 iifs 且没有否定接口条件才累加 accepted CIDR；UFW 路径要求没有 iface。新增 lo 反例在两个阶段和两种防火墙输入中均未达标，原假阳性已消除。对于合法的接口限定规则，当前策略仍是保守地不给出通用可达证明，而非断言该规则一定错误。

## BUG-055：链接清理生效，manager 转换仍属验收边界

两份恢复程序在 loader_enabled=enabled-runtime 时，仅清理 `/etc/systemd/system/{multi-user,sysinit}.target.wants/ssh-allowlist.service`，随后执行 enable --runtime；不存在单元分支也覆盖两个安装目标及 /etc、/run。

原新增测试使用普通文件模拟链接。本轮另将其替换为实际 symlink，再运行两份完整恢复程序，8 个链接覆盖两组相同场景，目标持久链接删除，运行期和 unrelated.service 链接保留。

该复核验证了真实文件操作，但 systemctl、服务保护属性和启用动作仍是桩件；不能据此宣称真实 systemd manager 的 enabled-runtime 转换或下一次冷启动已验收。生产修复本身可保留已修复状态，待补启动排序夹具并完成适用环境的集成验收。

## TST-016：正式启动排序夹具已修复

按用户要求，仅修改正式测试夹具及相关记录，未改变生产脚本。夹具补齐上文列出的 target 关键依赖边与 wants 安装链接：旧加载器链接到 multi-user.target.wants，新加载器链接到 sysinit.target.wants，socket 链接到 sockets.target.wants。verify 从 multi-user.target 展开依赖，不再把每个夹具单元都人为作为启动根。

保留旧/新配置对照：旧图必须输出涉及 ssh-allowlist.service 的 ordering cycle 诊断；新图必须返回 0 且无排序环。从单个启动目标展开时，systemd 可能删除弱依赖 Wants 任务以解环并返回 0，因此旧图不能只靠非零退出码证明问题；本轮实际观察到删除加载器启动任务的诊断。

修改前针对性用例复现失败，修改后该用例通过；Debian WSL（systemd 257）完整套件 136 项全部通过，无失败、错误或跳过。三脚本 ShellCheck warning 与套件内 bash -n 通过。三个生产脚本的 SHA256 与本轮修改前一致。

验证只使用临时文件和 systemd-analyze verify；没有启动/重载宿主单元、没有访问远端、没有真实冷启动，也不扩大为 OpenSSH 或 enabled-runtime 真实 manager 状态转换验收。
